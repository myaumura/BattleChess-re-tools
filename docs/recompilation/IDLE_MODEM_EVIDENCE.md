## Idle

The archive's idle sequences are assets, not evidence of scheduling. Rechecked
the only uses of static archive pointer `0xfc396`: initialization at `0x117b0`,
LOADBOAR index 4 at `0x1187a` (flat), index 0 at `0x1190a` (perspective). This
corrects the two reversed index labels in the earlier note. Its size-table pointer
`0xfc392` follows the same accesses (`0x117d8`, `0x11888`, `0x11916`). No index 2
idle read or direct `0xfd7aa`/`0xfd7ae` access was found. Searches also included
their A5 displacements `0x2856`/`0x2852`.

The one disassembled Random trap (`0x14a94`) selects an offset modulo `0x204f`,
backs up to `'*'` (`0x14aba`), then decodes text with XOR `0x6a` (`0x14ae8`). It
does not establish random idle selection. HANDLEAL's TickCount scheduler only
advances already-active graph records; it is not an idle trigger.

No automatic idle behavior was added. These negative searches cannot rule out
an indirect or unrecovered caller. Exact original trigger conditions remain
unrecovered; a timer/random-piece substitute would violate original-only scope.

The 2026-10-03 audit also scans aligned raw words across every recovered executable
CODE block, including bytes the decompiler failed to emit. The only C396 extension
words are at 0x117b2, 0x1187c and 0x1190c; C392 occurs at 0x117da, 0x1188a and
0x11918. D7A2 occurs only in the table initializer at 0x117ac (extension word 0x117ae).
No D7AA/D7AE idle offset-entry or D5EA/D5EE size-entry word occurs in those blocks.
The initialized A5 image also has no pointer alias into either static offset/size
table. LOADBOAR's actual next instructions read `[A0+0x10]` and `[A0]`, confirming
indices 4 and 0 rather than idle index 2.

The static offset table at 0xfd7a2 contains `(0,192,26903,27332,37520,37544)`;
the size table at 0xfd5e2 contains `(192,26711,429,10188,24,930)`. Thus the group
labelled idle by the extractor has metadata at archive1 offset26903 and compressed
data at27332. No original caller/selection/time gate was recovered. This direct-word
and initialized-alias audit cannot rule out computed aliases or an unrecovered
indirect path; idle activation remains absent in the native port.

The direct-word audit scans aligned words `c396`, `c392`, `d7a2`, `d7aa`,
`d7ae`, `d5ea` and `d5ee` across executable blocks in the private recovery model.
The byte/caller generator and its scope are described below; this inspection is
static evidence and does not establish a runtime trigger.

### Script and caller recovery — 2026-10-03

The saved byte audit (private workspace: `docs/recompilation/idle_evidence.json`) is generated by
[`idle_evidence.py`](../../tools/recompilation/idle_evidence.py). It freshly decodes archive1,
checks the saved two-bit pixels, reads the original shape selectors and
dispatch tables, and scans all nine CODE payloads for direct-transfer candidates.
Addresses in its `archive_offset` fields are archive1 offsets; call addresses
are original executable file offsets. A5 globals use the model's synthetic
`A5=0x100000` mapping. CODE bytes are read from that model after CREL
relocation. Six of its nine CODE payloads differ from the executable;
an additional canonical-byte check found identical direct-call candidates
and identical audited word hits. Relocation equivalence for these scans
does not establish reachability.

The 429-byte metadata block contains 32 delta shapes and twelve scripts,
producing **218 cumulative frames** from 22,235 decoded bytes. Every script's
selector is `0x80..0x83`: standing local shapes0..3, or original global
shapes17..20. The perspective selector table at `0xff314` maps these to
display type1, the **bishop** (engine type4), at orientations1,3,5,7.
These are twelve stored entries, not twelve different pieces. Entries4..7
are duplicated byte-for-byte as entries8..11.

The original metadata records shape geometry, compressed bit lengths,
base selectors and ordered delta indices. It supplies no trigger delay,
piece-selection rule or sound schedule. Those would require a caller/timing
stream; frame counts are not durations.

HANDLEEV's null-event entry in the sparse table at `0x102ce` points to
`0x102ee`. That branch calls `0x103b2`, which passes global `0xff198` to
the jump-table helper at `0x1d6da`. The helper copies Macintosh low-memory
Time (`0x20c`) to that global. This branch updates a clock value; it neither
selects a piece nor starts an animation.

Raw call scanning adds the PC-relative local calls omitted from the recovery
model's cross-segment call list. It finds five STARTANI and 59 WAITANIM calls,
all inside DOWALK. ACTIVATE has five direct callers: `0x133bc`, `0x137b0`,
`0x1382c`, `0x13fa2`, `0x141c6`, covering root/graph processing. SETUPSEQ has
three: `0x12878` in LOADMOVE and `0x12de4`/`0x12e64` inside CRUNCHAN's combat
loading paths, including the body that failed decompilation. HANDLEAL's
eight-way dispatch at `0x140ba` leads to the eight documented movement/combat
handlers, with no extra idle handler. The report also retains all fourteen
DISKSEEK and seven DISKREAD direct candidates for further loader tracing.

These aligned scans recognize A5 jump-table, PC-relative, absolute-long and
BSR transfers; embedded data can resemble instructions. They are **not a
complete reachable call graph**, and cannot resolve computed aliases or
indirect calls. The evidence supports a possible unused-asset explanation,
but does not prove that the Macintosh port never plays idle animations.
Automatic idle playback remains absent until its caller, selection and time
gates are recovered. No timer or RNG draw is inferred from the stored frames.

## Binary modem frames

`SENDBLOC 0x10ede` emits header, payload, then two checksums. Byte 0 has high
nibble `0xa`; byte 1's low seven bits give total frame length. READBLOC accepts
lengths below 40 (`0x1106e` vicinity). Checksums start at `0x20,0x30`, adding
alternating bytes modulo 256, including both header bytes but not the checksum.
Checksum comparisons are instructions `0x110e4` and `0x110f4`. The recovered C
incorrectly compares constant 0x20/0x30 there; native code follows instructions.

| Type | Payload | Evidence |
|---|---|---|
| A1 | 33-byte FILLSAVE board | SENDBOAR `0x112c2`, length 0x25 |
| A2 | destination byte, source byte, engine 0x88 squares | SENDMOVE `0x11316`, length 6 |
| A9 | promotion piece byte | SENDPROM `0x11370`, length 5 |
| A4 | none, negative acknowledgment | READBLOC `0x1112a`, literal A404C434 |
| A5 | none, acknowledgment | SENDGOTI `0x113b6`, literal A504C534 |
| A6 | none, status query after read timeout | SENDBLOC `0x10f6a`, literal A604C634 |
| AA | none, end/wait signal | WAITTOEN `0x3b50`, literal AA04CA34 |

CNFGETCO's switch data at `0x280e` routes A2 to `0x281e`, A1 to `0x2836`, A9 to
`0x2872`. A2 stores two pending-square bytes and acknowledges. A1 copies exactly
33 payload bytes into pending board data. A9 stores the promotion byte and
acknowledges. READBLOC's switch at `0x11108` consumes AA by setting `0xfcdcc`, and
A6 by sending A4 when receive-error flag `0xff1ce` is set, otherwise A5. SENDGOTI
clears that error flag.

SENDBLOC reads up to five responses (`0x10fd6..0x10fee`), sends A6 on timeout,
and retransmits on A4. Its same caller buffer is passed to READBLOC and later
reused for retransmission, so a naive corrected retry implementation is not a
verified instruction-for-instruction translation. Retry state is implemented separately in `modem_session.c`, preserving that
shared-buffer overwrite and the original fifth-response failure boundary. SERIALRE `0x114f0` has a per-byte deadline of current time+16;
the clock helper `0x1cdd0` reads Macintosh low-memory Time (`0x20c`), not TickCount.

ASCII modem/message lines are a separate path (`0x1117a..0x11292`): CR terminates,
LF is ignored at entry, control bytes below space do not advance the destination,
and empty lines / `ATE` are suppressed. The binary codec does not parse text.

## Native implementation and next host boundary

`lib/modem_protocol.c` implements only verified binary framing and checksum
validation. Native guards reject null buffers, excessive payloads, and total
lengths below four, instead of preserving malformed-input underflow. It accepts
the original masked length field on input. Complete-frame validation is not a
stream parser, command-specific payload check, move legality check, acknowledgment
state machine, modem initialization, or a playable modem backend.

`lib/modem_session.c` now supplies the original read/send-block control flow
through POSIX `open/read/write/poll/termios`, without new libraries. INITSERI's
config word `0x4d7c` is 300 baud, 8 data bits, no parity, one stop bit:
`380 + 3072 + 0 + 16384`. These constants are listed in Apple's
[Inside Macintosh II, Serial Drivers](https://puyoman.net/documentation/Inside_Macintosh.pdf).
Native cancellation and bounded text buffers are explicit host safety adaptations.

Selecting modem control at `0x649a`/`0x64e4` calls `0x3cae`, writing `ATE\r`
from initialized global `0xfae26`. There is no binary CONNECT handshake in that
path. DIALNUMB `0x39ca` builds `ATDT ` + dialog text + CR; lengths over 40 become
38, while 39/40 remain unchanged. HANDLEMO `0x10844` implements Dial, Hang Up
(`+++`, 180 TickCount delay, `ATH\r`), Auto Answer (`ATS0=1\r` / `ATS0=0\r`),
and Talk. GETSTRIN returns text length+1; SENDMESS then includes its terminating
NUL before CR, except the special `+++` escape sends three bytes. Native Talk
retains those bytes.

`--serial DEVICE` opens the native device and enables original MENU406 and
modem player selections. Dial/Talk use recovered DLOG405/404. Controller code2
is preserved in saves even without a configured device. `src/modem_host.h`
runs one finite serial operation asynchronously, queues outbound operations,
and joins on shutdown after signalling native cancellation. SDL state stays
on the UI thread. Device input remains binary-byte-compatible with the original;
PTY testing does not validate real modem electrical/driver flow control.

`main.cpp` routes local A2/A9 moves, A1 board replacement (33-byte FILLSAVE),
remote legal-move lookup, acknowledgment, original board-resync text, and AA
ending wait. Local promotion sends move/piece only after the choice, matching
FUN0x7630; remote promotion waits for A9. Original board-control selections send
ATE rather than inventing game negotiation. Native scheduling waits for network
completion before starting a local move animation and avoids overlapping active
animations. Original-runtime comparison and physical modem testing remain open.

The historical protocol sanitizer run passed. Its native check is
[`tests/modem_protocol_test.c`](https://github.com/myaumura/BattleChess/blob/main/tests/modem_protocol_test.c),
run through the [native build guide](https://github.com/myaumura/BattleChess/blob/main/docs/BUILD.md#checks-and-troubleshooting).

The check uses literal original ACK/query packets, exact move/promotion vectors,
single-byte corruption, malformed bounds and checksum wrapping at capacity.

Additional validation (passed): two-process PTY session test preserves original
NAK-buffer overwrite, ACK/status query, ASCII echo suppression, and dial bytes.

## Reviewed session boundaries

READBLOC `0x1122c..0x1125c` compares the first 20 bytes of incoming text with
`Your Opponent just quit`; it clears White's modem control first, otherwise
Black's. The native host now preserves that order and exits WAITTOEN when no
modem controller remains. This also completes a previously acknowledged ending
reset even if the quit-message alert replaced the ending alert.

Quit `0x2cd4 -> 0x3cbe` writes exactly 24 bytes: `Your Opponent just quit\r`.
Those 24 bytes exclude the C string's trailing NUL. Both File/Quit and SDL's
window-close event use the same native close path: cancel pending I/O, discard
queued game sends, send this line, and stop after completion or a two-second
native deadline. The descriptor is closed only after its worker joins.

A native input guard accepts A9 only for a matching currently pending promotion;
stale packets and invalid piece codes are acknowledged without discarding a
valid pending choice. A new A2, accepted A1, reset, or remote quit clears pending
promotion state. This validation intentionally avoids applying stale/invalid
external input to the legal game.

The actual-host PTY regression now runs twice, once for File/Quit and once for
SDL_QUIT. Each run covers A1 replacement, stale A9 before A1/A2, invalid promotion
codes 6 and 255 followed by a valid rook promotion, white-first remote quit,
terminal-wait exit on disconnect, and the exact outgoing 24-byte quit message.

Incoming modem chat retains original Mac Roman bytes on the wire; the host converts them to UTF-8 for the bitmap renderer. Unavailable/control glyphs use `?` instead of aborting rendering. The original three-second hang-up guard is split into cancellation-aware waits; normal completion still waits at least three seconds, while shutdown can interrupt it. A PTY cancellation check requires return within one second after cancellation and confirms that only `+++`, not `ATH`, was sent.

## Interoperability boundary checks — 2026-10-03

The extended real PTY check verifies the configured 300-baud, eight-bit, no-parity,
one-stop-bit settings. Literal peer traffic now covers three NAKs followed by a
fourth-response ACK (success), and four NAKs followed by a fifth-response ACK
(original failure). Both paths retain the overwritten six-byte retry body and
original checksum bytes. This follows the increment and `<5` checks at
0x10fd6..0x11006. Temporarily accepting the fifth ACK made the regression fail;
the production boundary was restored before the final 31/31 sanitizer pass.

The initial new peer closed immediately after ACK, producing a native I/O failure.
Keeping the PTY open until the sender consumed the response resolved that test
lifetime error; no production protocol change was needed. The actual SDL-host PTY
checks also pass. The host currently exposes only debug-console/Bluetooth callout
devices; no physical modem was identified in that device inventory. Original
traffic and a working original serial session are still unavailable. These checks
support native wire compatibility and transport behavior; original/native exchange,
dialing, electrical flow control and physical modem interoperability remain open.
